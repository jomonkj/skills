# Replace the yard orchestrator with a `/ship` skill driven by `/goal`

The yard orchestrator was a long-running daemon: cross-project collection, a TUI, Docker-isolated agents per issue, a state machine in code, multi-node coordination via GitHub labels, and a `fleet-state.json` snapshot. In practice the operator stopped running the daemon and instead drove work with the `ship-prd` skill plus Claude Code's `/goal` (a session-scoped Stop hook that re-prompts until a fast model confirms a completion condition). That path already worked.

We retire the daemon and formalise that path. The unit-of-work loop becomes: a `/ship` skill does **one batch** (resolve scope → dispatch unblocked work to parallel Agent subagents in git worktrees → return a summary); `/goal` re-invokes it each turn until every in-scope issue is terminal. The Claude session *is* the daemon. Docker isolation is replaced by `isolation: "worktree"` Agent subagents — acceptable because all targets are self-trusted repos. **All phases for one slice (implement → self-review → merge-check → open PR → ci-wait → squash-merge) run inside a single Agent call's conversation.** This is a hard constraint, not a style choice: the `Agent` tool has no `cwd` parameter and `isolation: "worktree"` creates a *fresh* worktree per call, so phases split across separate Agent calls would each get a different worktree and the chain would break. A builder must not "tidy" this into per-phase calls.

This is a big-bang cut, not a phased migration: the operator already validated `ship-prd + /goal`, so there is no daemon left to keep as a fallback. The old `yard` repo is archived (`yard.archived/`) read-only, keeping its ADRs and phase prompts as historical reference. The yard *name* survives where it is load-bearing — the `Yard` label, the `yd/` branch prefix, `.yard/config.yml`, and `.yard/worktrees/` — because renaming those is a far larger migration touching every onboarded repo for no functional gain.

What we lose: daemon survival across crashes, a bespoke TUI, multi-node coordination. None were in active use. What we gain: no separate process, no Docker, the loop lives in a normal resumable Claude session, and ~80% fewer tool calls once the plumbing moves into the `yard` CLI (see ADR 0003).

Auth/runtime consequence: the dispatch agents are `Agent`-tool subagents inside the Claude Code session, so they run on the session's own auth — **no `ANTHROPIC_API_KEY` is needed any more** (the daemon and the now-dropped review-sweep needed one). GitHub auth is still required but unchanged: standard machine-local `gh auth` (or `GH_TOKEN` for headless `claude -p`), never stored in config or synced (ADR 0006). No-Docker is an explicit accepted trade-off (no resource/network isolation, no clean-env guarantee); it holds only because every target is a self-trusted repo and must be revisited if untrusted code is ever shipped.

Open, deferred to follow-up grilling: the branch model (slices stacking on a PRD integration branch vs each PRD-ing directly to a main branch) — this is the lever that sets dedicated-review cost (see ADR 0004) — and the failure-escalation tier policy.
