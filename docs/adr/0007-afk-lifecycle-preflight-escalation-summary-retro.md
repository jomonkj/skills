# AFK lifecycle: pre-flight plan, escalation, orchestrator rescue, summary, retro

`/ship` runs unattended under `/goal`. The lifecycle around the dispatch loop is defined here so unattended runs fail safe and report honestly.

**Pre-flight is a mode of `/ship`, not a separate skill.** `/ship <scope> --plan` runs the same scope/deps/readiness resolution as execution, then stops before dispatch. A separate planning skill would drift from the executor and a plan that lies about what execution does is worse than no plan, because it gives false confidence right before an 8-hour unattended run. The plan separates two things: a **genuine choice** (ship order, ambiguous difficulty, cross-repo strategy) is asked grill-style — one question, A/B/C, recommendation, wait; a **hard readiness gap** (no acceptance criteria, a dependency cycle) is not a question but a blocker that holds the plan at NO-GO. The plan ends with an explicit GO / NO-GO line and, on GO, the exact copy-pasteable `/goal` command, written to the goal docs' rules: one measurable end state, a stated check Claude's own output demonstrates (so it must reference the run-summary contract below, since the evaluator judges only from the conversation), and a turn/time bound clause to cap runaway.

**Escalation is two-tier: sonnet → opus → HITL.** Haiku rarely completed real implementation work in yard runs, so sonnet is the floor and opus the rescue; the haiku tax is skipped. A "slice fails" when, within a tier's iteration budget, it does not reach a *verified* `COMPLETE` — explicit `CANT_FIX`, budget exhausted, self-review never passes, change-gate tests stay red, unrecoverable crash, or dedicated review returns unfixable hard findings. Three terminal states are kept distinct so nothing is silently lost: **fail** (escalate a tier), **HITL** (all tiers exhausted, human needed), **blocked** (waiting on a dependency — not a failure). `CANT_FIX` escalates immediately rather than burning the remaining budget; at the top tier it routes to HITL. HITL is never silent: a `phase:hitl` label, a reason comment on the issue, and a line in the run summary.

**Fixed v1 defaults, no config surface.** Parallelism cap = **3** concurrent slices. Stale-lock timeout for `phase:implementing` = **2 hours** (after which the lock is reclaimable, so a crashed dispatch can't wedge a slice forever). These are pinned, not configurable in v1 — same "no knobs until dogfooding forces them" discipline as ADR 0004. The per-tier **iteration budget** is *deliberately deferred* to dogfooding tuning rather than guessed now; "budget exhausted" in the failure definition refers to whatever that tuned value becomes.

**Conditional orchestrator rescue before HITL.** The orchestrating `/ship` session sees what a single-slice subagent cannot — the whole PRD, sibling diffs, the dependency graph. Many "failures" are actually cross-slice (a sibling changed an interface). So before declaring HITL the orchestrator makes **one bounded rescue attempt, but only when the failure smells cross-slice** (integration error, sibling interface change, a dependency just merged). For a raw "task too hard" `CANT_FIX` with no cross-slice signal it goes straight to HITL — an orchestrator retry there only burns tokens. This serves the operator's standing goal of minimising HITL without spending on hopeless retries.

**The run summary is a defined contract, dual-purpose.** It is both the human report and the text `/goal`'s evaluator reads to decide done, so it must be deterministic and terminal-state-complete: every in-scope unit resolved to `merged | awaiting-human-merge | hitl | failed | blocked`; HITL items with reasons and links; conflicts (auto-resolved / semantic-with-rationale / HITL); forward-merge hop results; dedicated-review outcomes (pass / soft-followups-filed / hard-escalated); follow-up issues filed with links; and cost — tokens, dollar estimate, wall time, dispatch count, escalations per tier. Cost is **summed from the session/usage logs, never a last-message snapshot**: a prior yard metric bug undercounted by ~128× because it snapshotted instead of summing; that mistake must not recur.

**Long test suites never block a `/goal` turn.** The per-slice change gate runs only the *affected* tests (what the diff touches) — fast, seconds-to-minutes, synchronous. The feature→release-line intent gate requires the *full* suite, which in some projects takes hours; that suite is fired **asynchronously** (CI/background), the PR sits behind a `tests-running` label, the loop moves on to other work, and a later turn reconciles it — flipping to `AWAITING_HUMAN_MERGE` on green or HITL on red. `yard ci-wait`'s bounded poll is used only for short gates; a multi-hour suite is fire-and-track via labels, never a blocking wait, because a hung wait stalls the whole unattended run.

**Self-healing and self-improving are split.** Self-healing (retry, sweep, reconcile) is mechanical and already lives in `yard`. Self-improving is a post-run **retro pass** that inspects the run for *workflow*-health problems (repeat same-tier failures, conflict hotspots, recurring under-specified-issue patterns) and files them as `workflow` follow-up issues. It only reports and suggests; it never auto-modifies the workflow. Automated self-modification of the workflow is out of scope by deliberate decision — it is the highest-risk possible behaviour and stays human-gated.

The two repo-onboarding setup skills (`setup-yolo-skills`, the renamed `setup-yard`) are merged into one `setup-yard` skill with a `--triage` flag for the lighter triage-only mode; both modes delegate all label creation to `yard labels-ensure` so colours and descriptions have one source.
