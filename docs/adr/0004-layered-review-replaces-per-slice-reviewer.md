# Layered review replaces the per-slice Reviewer and review-sweep

The old model spawned a fresh Reviewer agent per slice and ran `review-sweep` as a post-hoc label-driven audit over done items. The per-slice Reviewer cold-starts every time — re-reading repo, diff, and issue (~20–30K input tokens per slice). `review-sweep`'s code lived in the yard repo (archived) and made an Anthropic call, violating the "no AI in yard" rule (ADR 0003). Both are retired.

The replacement is three layers, ordered cheapest-first:

1. **Implementation rules (prevent).** A generic `implement.md` prompt makes the implementer read the repo's existing truth — `CLAUDE.md`, `CONTEXT.md`, ADRs touching the area, the issue AC — *before* coding. No new `RULES.md`: that would duplicate and drift from `CLAUDE.md` and violate the project's one-source truth-flow. The prompt points at the `review` skill's two axes (Standards, Spec) as the definition of done, so implementer and reviewer share one rubric.

2. **Self-review (cheap pre-pass).** Before emitting `COMPLETE`, the same agent checks its own diff in its warm context — no new agent. It is mechanical (a quoted-evidence checklist per AC line and per cited standard, not a "looks good" judgement) and calibrated (it states its own author-bias limitation, so the system never mistakes it for the real gate). Same-agent blind spot is structural and cannot be eliminated; the design bounds its claim rather than pretending otherwise. Adversarial framing was considered and rejected as theatre — the mechanical checklist is the real defence.

3. **Dedicated review (the real gate).** An independent fresh agent runs the promoted `review` skill — two axes, Standards and Spec — at the unit-of-delivered-intent boundary. Findings follow a severity split (carried over from the retired ADR 0027): hard findings (a spec requirement missing or wrong) keep the unit open and escalate to a human; soft findings file follow-up issues and let the loop self-heal.

The `review` skill is **promoted from `skills/in-progress/review/` to `skills/engineering/review/`** and **re-wired to yolo conventions**: its upstream-Matt references (`/setup-matt-pocock-skills`, `docs/agents/issue-tracker.md`) are replaced with direct `gh` / `yard` plumbing and the yolo issue-tracker assumptions. It is invoked two ways: automatically by `/ship` at the intent boundary (and on a blast-radius slice), and **manually, human-triggered**, to deep-review a branch/PR on demand. The manual mode is not part of the AFK `/goal` loop. As an `engineering/` skill it must be added to the top-level `README.md`, its bucket `README.md`, and `.claude-plugin/plugin.json` per the skills repo `CLAUDE.md`, and removed from the `in-progress` listings.

The review unit is the **unit of delivered intent**, not the dispatch unit: a PRD (reviewed when its last slice merges, against the combined diff) or a parentless issue (reviewed on merge, against its AC). A slice is a fragment — change gate only; its intent rolls up to its PRD. This closes the gap where a standalone bare issue previously got only a fragment-level review.

Status: accepted and closed. The branch model (ADR 0005) resolved the previously-open parameter. The dedicated review fires at the unit-of-delivered-intent boundary, which ADR 0005 makes concrete: the feature→release-line PR (so once per PRD) and the parentless-issue→release-line PR (once per bare issue). It additionally fires early on a **high-blast-radius slice** — any slice with dependency fan-out ≥ 2 in the graph `yard scope` already builds. This is a scheduling rule on existing data, not new machinery: it only changes *which* slices get the existing dedicated review early versus deferred. The threshold is fixed at 2 with no v1 config surface. Adversarial self-review framing was rejected as theatre; mechanical evidence-checklist plus calibration is the whole of self-review. The residual risk — a wrong assumption in a foundational slice propagating before the boundary review — is precisely what the blast-radius early trigger covers, since foundational slices are by definition high fan-out.
